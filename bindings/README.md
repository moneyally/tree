# App bindings

`crates/tree-ffi` exposes the whole client (`tree_client::Session`) through
UniFFI (the `uniffi` crate) as one object,
`TreeSession`, plus records and a `TreeEvent` enum. The apps call it from a
background thread: every call blocks (network, Argon2id). Group and member
ids are lowercase hex strings.

| Language | Used by | Generated by | Checked here |
| --- | --- | --- | --- |
| Kotlin | Android app, desktop app (Compose Multiplatform, JVM) | `sh scripts/gen_bindings.sh` | `sh scripts/ffi_kotlin_demo.sh`: runs on the JVM through JNA against a local server |
| Swift | iOS app | `sh scripts/gen_bindings.sh` | generated only (needs macOS to compile) |
| Python | tests | `sh scripts/gen_bindings.sh` | `sh scripts/ffi_demo.sh`: sign-up, @username, group, text, file, safety number, report, invite link, recovery, wrong passphrase |

Errors arrive as `TreeError` (Kotlin: `TreeException`) with the server's
code (`Server`), a feature-registry code (`Feature`, e.g. `LOCKED_BY_CHAT`),
`WrongKey`, `Network`, `Usage` or `Other`.

Typical app loop: `TreeSession.create(...)` once (then `open(...)` on every
start), `setPushEndpoint(...)` with the push gateway's endpoint, then on
every wake-up or while the app is open `sync(wait)` and show the events.
Settings screens come from `features()` with `applyFeature` /
`releaseFeature`; `lockedBy` says why a switch is disabled.

Android NDK and Xcode), the apps themselves.
